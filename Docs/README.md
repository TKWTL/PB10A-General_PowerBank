# Docs

技术文档与实验记录。代码之外需要长期保留的证据都放这里，**不要写进 README 的流水账**。

建议按用途分目录（首次使用时自行创建）：

| 目录/文件 | 内容 |
|---|---|
| `RELEASE.md` | 发布流程与检查清单（含 `相关数据手册/` 的删除时机） |
| `GIT_WORKFLOW.md` | Keil 工程文件（uvprojx/uvoptx）的远程同步与冲突处理 |
| `Experiments/` | 实验报告：目的、条件、原始测量、结论与失效前提 |
| `Protocol/` | 通信协议、寄存器映射、时序约定 |
| `Interface/` | 硬件接口、引脚分配、上下电时序 |
| `Bringup/` | 首次上电与硬件台架验证记录 |
| [`Debug/`](Debug/README.md) | 可复用的故障现象、Keil 定位路径、低功耗时序、修复与验证记录 |

约定：

- 一份报告一个文件，文件名带日期或版本（`2026-01-20_buck_ripple.md`）。
- 结论必须写适用条件与已知失效边界，避免后人把单点测量当全工况结论。
- 原始数据（CSV/波形截图）放同目录的 `<报告名>_data/`，`Images/Testing/` 只放需要公开展示的图。
