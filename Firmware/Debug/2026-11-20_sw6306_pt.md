# SW6306 协程化与低功耗状态交接

日期：2026-11-20
状态：源代码已提交，Keil 全量编译与板上回归待验证

## 架构

- `Firmware/BSP/SW6306/sw6306.h` 已启用 `SW6306_USE_PROTOTHREAD`。
- `PowerAlgo_SW6306Thread()` 为**唯一后台操作所有者**，仍使用
  第六个 coroOS 线程槽，执行初始化与 ADC/状态/端口/功率/容量分相读取。
- 驱动函数返回 Protothreads 状态（WAITING/YIELDED/EXITED/ENDED）。
  每次 I²C 传输通过 `Core/Src/i2c.c` 的 HAL 中断接口提交；
  等待时仅挂起调用的 SW6306 协程，其他任务照常执行。
- 旧 SC7A20、BMP180、MMC5603、RDA5807 的同步兼容调用未改动。

## 完成标志、超时和缓冲区

- `SW6306_Status.flag` 使用 volatile，0 为未完成，1 为成功，
  2 为错误。只有 HAL 接受事务后，子协程才等待完成标志。
- 等待总线准入最长 100ms；未被接受的事务可以直接失败，不会
  丢弃已经交给 HAL 的传输缓冲区。
- 一旦 Core I²C Abort 进入不可恢复状态，后续异步请求立即
  以 ERROR 结束，而不是一直等待可用总线。
- `ADCLoad`、`StatusLoad`、`PortStatusLoad`、`CapacityLoad`
  及 `PowerLoad` 均使用静态缓冲区，跨 PT 让出点不会引用失效栈变量。
  完整读取成功后才统一更新镜像；读失败保留旧值并降低数据有效性。
- `SW6306_OperationReset` / `SW6306_LastOperationOK`
  跟踪每项操作的错误；状态与端口使用成功读取序号防止旧缓存
  被误判为新数据。

## 初始化和休眠

- 唤醒/解锁仍执行 LPSET=1、等待约 2ms、读取 REV、
  必要时切换低寄存器页，再写 WREN 序列 0x20/0x40/0x80。
- 初始化只有在解锁并完成所有配置读写后才宣布成功。
  失败不覆盖为 initialized=1，延迟约 5s 重试。
- SW6306 操作期间 `s_sw_owner_busy` 为真。PM 准备阶段
  等待已经开始的事务结束，禁止同时占用驱动 PT 状态。
- STOP1 前异步调用 `PortStatusLoad`，要求成功序号增加且
  实时缓存确认所有接口空闲；随后异步调用 LPSET。
  唤醒或中途取消时必须先耗尽尚未完成的 I²C，才能发起解锁。
- SW6306 内部的 PT_MUTEX 是空操作；这是因为唯一操作所有者
  已保证不会出现递归进入。同一 SW6306 驱动不可被 UI、其他任务
  或中断直接并行调用。未来运行时功率/协议设置应加入所有者命令队列。
